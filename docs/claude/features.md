# Feature notes

Per-feature decisions that aren't obvious from the code. Read the section for a feature before changing it, or one that is FK-related to it. Full specs are in `spec/{sub-system}/{Table}.md`. Add a section here when you build a new feature, and add its name to the `features.md` pointer in CLAUDE.md.

## AppRole — 系統管理 Admin › 角色 (`database/auth.sql`)
- **Admin role only**: class-level `[Authorize(Roles = "Admin")]` (403 `{ message }`), since role membership decides who is Admin. Lookups (`api/lookups/app-roles`) stay open to any signed-in user.
- Table PK `RoleId` (nvarchar), immutable on update (referenced by `AppUserRole`); `pkid` used for routes/PUT. Duplicate → 409.
- n-n users via `AppUserRole` (string keys): `UserIds: List<string>`, `UserCount` in list, `Users` on GET by id. Delete removes `AppUserRole` rows first. Create/update trim the ids, de-duplicate them case-insensitively (the DB collation, so the `(UserId, RoleId)` PK never sees a repeat) and reject unknown ones with 400 `使用者 … 不存在` (`CheckUsersAsync`), mirroring AppUser's role check. Updates audit added/removed members in the AppRole Update row (`UserIds +bob -carol`).
- Filters: keyword (RoleId, RoleName, Description), `permissionLevelFrom`/`To`. Sort `RoleId ASC`. `Description` optional; `PermissionLevel` defaults to 100.
- Lookup `app-users` (ordered by UserName). Detail page's user count links to `/app-users?roleId=`.

## AppUser — 系統管理 Admin › 使用者 (`database/auth.sql`, `spec/auth/AppUser.md`)
- Table PK `UserId` (nvarchar), immutable on update; `pkid` used for routes/PUT. Duplicate → 409.
- **Admin role only** (whole controller, `AppUsersController.AdminRole`, 403 `{ message }`): before this a `User` could PUT itself into `Admin` and issue anyone's agent token. `api/lookups/app-users` stays open (Token 用量 filter).
- **`PasswordHash` never leaves the backend** (no model has it; the SELECT skips it). Format: lowercase hex SHA-256 of the UTF-8 password, unsalted (`Security/PasswordHasher`), matching existing rows.
- Create hashes `SysConfig['appConfig'].defaultPassword` and sets `PasswordUpdatedTime = NULL`. Update never touches the password. `POST /api/app-users/{id}/reset-password` restores the default hash and sets `PasswordUpdatedTime = NULL` (back on the default password; RowAudit records when and who); Admin only (controller-wide), 204 with no body. UI: shared `reset-password-button/` (confirm, Admin-only via `AuthService.isAdmin`) on the detail page and the edit form; sends only the pkid. Missing appConfig/defaultPassword → 500 `{ message }`.
- n-n roles via `AppUserRole`: `RoleIds: List<string>`, unknown ids → 400 (`CheckRolesAsync`). Delete removes the user's role rows first. Updates audit added/removed roles in the AppUser Update row (`RoleIds +Admin -User`, `RowAuditWriter.MemberChange`), so granting Admin is traceable.
- Filters: keyword (UserId, UserName), tri-state `isActive`, `roleId` (also `?roleId=`). Sort `UserId ASC`.
- Lookup `app-roles` (`{ pkid, roleId, roleName }`, by RoleId).
- No password field in the form (new mode shows a default-password hint). `PasswordUpdatedTime` is displayed as returned (no `'Z'`); NULL shows 尚未變更（預設密碼）.
- Data: seed user `admin@example.com` (pkid 14, role `Admin`), roles `Admin`/`User`. The default password lives only in `SysConfig` (never copy it into the repo, which is public).

## Auth (login, JWT authorization) — `/login` (`database/admin.sql`)
- `POST /api/auth/login` `{ userId, password }` → 200 `{ userId, userName, accessToken }`. `AuthController` + `IAuthRepository` (own repo; `LoginUser` is the only model holding `PasswordHash`, never returned).
- Checks: UserId **exact** (the DB collation `Chinese_Taiwan_Stroke_CI_AS` is case-insensitive and `=` ignores trailing spaces, so the controller re-compares ordinally), `IsActive = 1`, `PasswordHash` = SHA-256 hex (constant-time, hex case ignored). Any failure → 401 `{ message: "帳號或密碼錯誤" }`, identical for every reason.
- JWT (`Security/AccessTokenIssuer`, `Microsoft.IdentityModel.JsonWebTokens`): HS256 signed with `SysConfig[appConfig].symmetricSecurityKey` (UTF-8 bytes, read per request, must be >= 32 bytes; else 500 `{ message }`). Claims `sub` = UserId, `name` = UserName, `role` (array, one per `AppUserRole.RoleId`, omitted when none), `jti`; `iat`/`nbf` = now (`TimeProvider`), `exp` = +24h. No issuer/audience.
- **Validation** (`Security/JwtAuthentication.AddCmsJwtAuthentication`, `Microsoft.AspNetCore.Authentication.JwtBearer`): the key is re-read from SysConfig per request in `OnMessageReceived` (stashed in `HttpContext.Items` for the sync `IssuerSigningKeyResolver`), so key rotation applies at once and a missing key → 401. HS256 only, no issuer/audience, clock skew 1 min, `MapInboundClaims = false` (`name` / `role` claim types). `cms_at_` bearers are skipped (NoResult). Challenge → 401 `{ message: "請先登入" }` + `WWW-Authenticate: Bearer`.
- **Global policy**: `app.MapControllers().RequireAuthorization()`. Only `AuthController.Login` and `AgentTokenUsagesController.Report` (the SessionEnd hook, which has its own `cms_at_` token) are `[AllowAnonymous]`; `AuthorizationTests` asserts that exact list, so a new anonymous action must be added there. Role-based authorization (`Admin`; a 403 carries `{ message }` from `JwtAuthentication.OnForbidden`) on everything under the adminOnly 系統管理 menu: the AppUser, AppRole and PublishStatus controllers, the Token 用量 report (`query`, `filter-options`) and RowAudit history of AppUser/AppRole. Every other endpoint, including all `lookups/*`, is open to any signed-in user. `AuthorizationTests.Protected` must stay an endpoint without a role limit. Swagger UI has an Authorize button (Bearer).
- **Frontend** (`core/auth/`): `AuthService` keeps `{ userId, userName, accessToken }` in **sessionStorage** key `auth-profile` (never localStorage); roles are decoded from the token's `role` claim (string or array, unsigned decode). `authInterceptor` adds `Bearer` to requests under `environment.apiUrl`; any 401 except from the login URL → `sessionStorage.clear()` (also drops saved list filters) + `/login?returnUrl=`; any 5xx (login included) → 系統錯誤 toast, session kept. `authGuard` (`canActivateChild` on a componentless `''` parent of all app routes) checks token presence and `exp`, clearing a stale session; `loginGuard` sends signed-in users home. `/login` is outside the shell: `app.html` renders sidebar + header (UserName, 登出) only while `auth.profile()` is set. `returnUrl` is restricted to same-app paths (`safeReturnUrl`).
- **Menu by role**: `NavGroup.adminOnly` (系統管理 Admin) shows only when roles include `Admin` (exact). Home redirect is a function: Admin → `/app-roles`, others → `/featured-promo-items`. Admin routes are not role-guarded (hidden from the menu only; a non-admin who types `/app-users` or `/app-roles` gets the API 403 toast).
- **My Profile** (`/profile`, header UserName links to it): `GET api/auth/profile` → `{ userId, userName, roles: [{ pkid, roleId, roleName }] }`; `PUT api/auth/profile` `{ userName }` (required, max 200, trimmed, whitespace-only → 400) updates only `AppUser.UserName` of the JWT `sub` user. `UserProfileRequest` has no UserId/roles, so body values for them are never bound. Row gone → 404 `{ message }`. The frontend then rewrites `userName` in the stored `auth-profile` (token unchanged, so its `name` claim stays stale until the next login; nothing reads it). Page: UserId and role chips read-only, one input.
- **Change password** (My Profile page, own `passwordForm` below the profile form): `POST api/auth/change-password` `{ currentPassword, newPassword, confirmPassword }` → 204, for the JWT `sub` user only. Order: current password SHA-256 must match (constant-time) → else 400 `目前密碼錯誤`; complexity (`Security/PasswordPolicy`: length ≥ 8 and ≥ 3 of upper A-Z / lower a-z / digit / ASCII symbol; space and CJK count as no class) → else 400 with the bilingual `PasswordPolicy.Message`; new ≠ confirm (ordinal) → 400 `新密碼與確認新密碼不一致`. Every failure is **400, never 401** (the interceptor would sign the user out). Success sets `PasswordHash` = SHA-256(new) and `PasswordUpdatedTime` = Taipei now (UTC+8 via `TimeProvider`); the session/token stays. Always enforced, regardless of `appConfig.enforcePasswordPolicy`. The frontend mirrors the rule in `core/auth/password-policy.ts` (same message, shown under 新密碼 with `white-space: pre-line`); keep both in sync. No hash is ever sent either way.
- Deferred: no frontend route guard for admin pages (a non-admin who types the URL gets the API 403 toast), refresh token / sliding expiry, server-side logout (tokens stay valid until `exp`).

## PublishStatus — 系統管理 Admin › 發布狀態 (`database/admin.sql`, `spec/admin/PublishStatus.md`)
- **Admin role only** (whole controller, 403 `{ message }`); `api/lookups/publish-statuses` stays open (Course form/filters).
- PK `pkid` **tinyint, not IDENTITY** (C# `byte`): entered on create (1–255, duplicate → 409), disabled on edit.
- Referenced by `Course`, `Promotion2`: `CourseCount`/`Promotion2Count`; in use → DELETE 409.
- Filters: keyword (Description), tri-state `isDraft`/`isPublished`/`isDiscontinued`. Sort `pkid ASC`.
- Lookup `publish-statuses` (`{ pkid, description }`, by pkid).
- Data: 1 草稿 / 2 上架中 / 3 已下架, all in use. Course count links to `/courses?publishStatusPkid=`; Promotion2 link deferred.

## Partner — 課程管理 Course › 原廠 (`database/course.sql`, `spec/course/Partner.md`)
- PK `pkid` **smallint IDENTITY** (C# `short`).
- `AppKey` (varchar 10) unique in the API only → 409 on create/update. `AppKey`/`ImageFilename` are varchar (ASCII, AnsiString). Blank `ImageFilename` → NULL.
- Referenced by `Course`, `Certification`, `PartnerCourseGroup`, `Promotion2.RelatedPartner_pkid` (FKs) and `Seminar.Partner_pkid` (**no FK**). All five counts in the SELECT; DELETE → 409 if any > 0. List shows course/certification counts, detail all five.
- Filter: keyword (Name, AppKey, NameOnPartnerMenu, NameOnCourseDetailPage, ImageFilename). Sort `DisplayOrder ASC, pkid DESC`.
- Lookup `partners` (`{ pkid, name }`, by DisplayOrder, Name).
- Data: 66 rows, most in use. Course count links to `/courses?partnerPkid=`; Promotion2 will use `relatedPartnerPkid`.

## CourseGroup — 課程管理 Course › 課程群組 (`database/course.sql`, `spec/course/CourseGroup.md`)
- `pkid` (**smallint IDENTITY**) + `Description` nvarchar(100) (label 群組名稱). Description is **not** unique (existing duplicates).
- Referenced by `Course.CourseGroup_pkid` (nullable) and `PartnerCourseGroup.CourseGroup_pkid`: both counts in the SELECT; in use → DELETE 409. (`Promotion2.RelatedPartnerCourseGroup_pkid` points at `PartnerCourseGroup`, not here.)
- Filter: keyword (Description). Sort `pkid DESC`.
- Lookup `course-groups` (`{ pkid, description }`, by Description; 215 items → filter + virtual scroll).
- Course count links to `/courses?courseGroupPkid=`.

## Course — 課程管理 Course › 課程 (`database/course.sql`, `spec/course/Course.md`)
- PK `pkid` int IDENTITY. FKs `Partner_pkid` (smallint), `CourseGroup_pkid` (smallint, **nullable**), `PublishStatus_pkid` (tinyint), JOINed for `PartnerName`, `CourseGroupDescription` (LEFT), `PublishStatusDescription`.
- **List SELECT leaves out the 8 long-text columns** (`Outline`/`TowardCertOrExam` are nvarchar(max)); GET by id fills them plus n-n `Certifications`/`JobCategories`.
- `CourseId` (varchar 50) unique in the API (409); `ProdCourseId`/`FriendlyUrl` may repeat. `CourseId`/`ProdCourseId` ASCII + AnsiString.
- 400s: bad FK/n-n ids (`CheckReferencesAsync`), `ScheduleOff < ScheduleOn` (one existing row breaks this), `ListPrice` with decimals, `LearningCredit` with more than one decimal.
- n-n `CourseInCertification` (`CertificationPkids`), `CourseJobCategories` (`JobCategoryPkids`); DB cascades on delete. `Certification.Title` is nchar → RTRIM.
- Delete guard: `CourseFAQ`, `CourseRelatedLink`, `HotCourse` → 409. `CourseRecomm` is keyed by the **CourseId string** (no FK, 895 orphans): delete removes rows on both sides; a rename updates `CourseId`/`RecommCourseId` in the same transaction.
- Filters: keyword (Title, OfficialTitle, CourseId, ProdCourseId, FriendlyUrl), partner / course group / publish status, ScheduleOn/Off ranges (inclusive), tri-state canRepeat. Sort `DisplayOrder ASC, pkid DESC`. Accepts `?partnerPkid=` / `?courseGroupPkid=` / `?publishStatusPkid=`.
- New form defaults: ScheduleOn = today, ScheduleOff = Dec 31 of next year.
- Lookups: `certifications` (`{ pkid, title, partnerName }`), `job-categories`, `courses` (`{ pkid, courseId, title }`).
- Detail page 基本資料 shows a QR code (`<app-qr-code>`) of the public page `https://www.uuu.com.tw/Course/Show/{pkid}/{CourseId}` (`COURSE_SITE_URL` in `course-detail.ts`; CourseId is URL-encoded), titled with the CourseId and downloadable as `{CourseId}.png`.
- **List page in-place editing** (`course-inline-edit.ts`): double-click any cell except 主代碼 / 原廠 / 課程群組; saved on blur (Enter commits, Escape cancels). Because list rows omit the long texts and n-n arrays and PUT replaces everything, a save does `getById` → `toCourseRequest(full, patch)` → `update`. Client validation mirrors the form/API (required, ASCII codes, non-negative numbers, 定價 integer, 點數 one decimal, valid dates, 上架日期 ≤ 下架日期) and keeps the cell open with an inline `.cell-error`; API 400/409 reverts the row and toasts `message`. 上架狀態 edits load the lookups on first use.
- Not built (from `spec/sample1.spec.md`): copy, print to PDF, CourseRelatedLink / CourseRecomm sub-panels.

## FeaturedPromoItem — 首頁 Home › 上稿作業 (`database/promotion.sql`, `spec/custom/FeaturedPromoItem/`)
- Custom UI from screenshots, not the list/detail/form template: one route `/featured-promo-items`. Training-center tabs (`lookups/training-centers`, by DisplayOrder: 台北/新竹/台中/高雄/線上研討會; pkids 1,2,3,5,54), a Monday–Sunday week navigator, and per day 3 slot rows with +/− (move down/up), 編輯, 複製/貼上, 刪除. The editor opens inline in the row (`FeaturedPromoItemForm`, used for Edit, New and Paste).
- PK `pkid` int IDENTITY. FKs `TrainingCenter_pkid` (smallint), `Promotion_pkid` → `Promotion2` (JOINed for `TrainingCenterName`, `PromoCode`). **UNIQUE (ScheduleOn, TrainingCenter_pkid, Slot)** → API 409 `{ message }`. Slot is 1..3 (`MaxSlot`).
- **No GET-all** (31.7k rows since 2019). `POST /query { trainingCenterPkid?, weekOf? }` returns the Mon–Sun week containing `weekOf` (default: this week, via `TimeProvider`), ordered by date, center DisplayOrder, slot.
- `POST /{id}/move-up` / `move-down` swap with the neighbor slot (or just move into an empty one) through slot 0 in a transaction; 400 at the edges. Moves are not row-audited (Create/Update/Delete are).
- PromoCode autocomplete: `GET /api/lookups/promotions?keyword=` (top 20, exact match first, then newest; `_` escaped). Picking one sets `promotionPkid` and prefills Topic/Description from `Promotion2` (both still editable).
- Copy keeps `{ promotionPkid, promoCode, topic, description }` in a component signal (not persisted); Paste is only offered on empty slots and opens a prefilled New form. Selected tab and week are kept in session (`featured-promo-item-list-filters`).
- Smoke-test in far-future dates (e.g. 2099) on center 54, and check for leftover `Slot = 0` rows.

## AgentTokenUsage — 系統管理 Admin › Token 用量 (`database/agent.sql`, `spec/agent/AgentTokenUsage.md`, `tools/token-report/`)
- **New tables, hand-written DDL** (`database/agent.sql`, re-runnable): `AgentTokenUsage` PK (SessionId, UsageDate, Model), FK UserId → AppUser, `SessionName` nvarchar(200) NULL (same on every row of a session); `AgentModelPrice` PK (Model, EffectiveFrom), USD per MTok for input / output / 5m write / 1h write / cache read; `AppUser.AgentTokenHash` nvarchar(64) NULL with a **plain** index (a filtered/unique one broke `AppUser` INSERTs from `sqlcmd`, which runs with QUOTED_IDENTIFIER OFF).
- Capture is a Claude Code **SessionEnd hook** (`tools/token-report/report.js`, Node, no deps), installed per developer in `~/.claude/settings.json` with `timeout: 30`; config in `~/.claude/token-report.json`. It parses the main transcript + `<session>/subagents/*.jsonl`, **counts each API call once by `message.id`** (the transcript repeats a call on several lines — ~2.5× over-count otherwise), last line wins; drops `<synthetic>` and all-zero rows; date = UTC timestamp + 8h. Session name = last `custom-title` (`/rename`), else last `ai-title` (Claude Code rewrites it during the session), capped at 200; null when neither (parser version 2). Project = origin remote repo name → git root folder → cwd folder. Outbox `~/.claude/token-report/outbox/`: 2xx delete, 404 (API not yet restarted with the endpoint)/408/429/5xx/offline retry next session, other 4xx → `failed/` (`--retry-failed`). `--backfill` sends every transcript still on disk. All transcript-format assumptions live in `lib/parse.js` (`PARSER_VERSION`, stored per row).
- `POST /api/agent-token-usages` (204): `Authorization: Bearer cms_at_…`, SHA-256 looked up in `AppUser.AgentTokenHash` (active users only); the payload has no userId. Bad/missing token → 401 `Agent Token 無效`. Validation 400s: sessionId 1–100, sessionName ≤ 200 (blank → NULL), project 1–200, parserVersion 1–20, 1–500 rows, model 1–100, no negative / all-zero token rows, each token field ≤ 1e12 (`MaxTokens`, keeps Cost decimal(18,6) and the report SUMs from overflowing), duplicate (date, model), usageDate within [Taipei today − 400, today + 1]. Session owned by another user → 409. **Replaces all rows of the session** in one transaction (resume/retry/backfill are safe). Not row-audited (machine ingest).
- Cost is computed server-side: the `AgentModelPrice` row with the latest `EffectiveFrom <= UsageDate` (`AgentModelPrice.For` / `CostOf`, rounded to 6 dp); no price → `Cost NULL`, row still stored, report shows 未定價. Seeded from the pricing page on 2026-10-20 (Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5 ≤100K tier); fast mode / US-only inference / Haiku long-context surcharges are not modelled. Prices are edited in the DB (no screen).
- "Taipei today" on the server = `TimeProvider.GetUtcNow()` + 8h (never `GetLocalNow()`); `UpdatedTime` is Taipei time.
- Report: `POST /query { from?, to?, userIds[], projects[], models[], groupBySession }` (dates default to the current Taipei month) → rows grouped by (date, user, project, model) (plus SessionId when `groupBySession`, with `sessionId` / `sessionName` filled, unnamed sessions sorting first) with `sessionCount`, token sums, `cost` (sum of priced rows) and `hasUnpricedRows`; `GET /filter-options` → distinct projects/models; users come from `lookups/app-users`. Page `/agent-token-usages`: inline filter bar (date range, multi-selects, 依工作階段 toggle that adds a 工作階段 column, falling back to （未命名）+ the first 8 characters of the id, full id in the tooltip), Cache write = 5m + 1h, Token in = input + writes + reads, grand-total footer, no paging; filters in session `agent-token-usage-report-filters`.
- AppUser: `hasAgentToken` and `agentTokenUsageCount` in the model (hash never sent). `POST /api/app-users/{id}/regenerate-agent-token` → `{ token }` (`cms_at_` + 32 random bytes base64url, shown once in a dialog with copy), `/revoke-agent-token` → 204. AppUser DELETE → 409 while usage rows exist.
- Auth: ingest (`POST`) is `[AllowAnonymous]` and checks the `cms_at_` token itself; the report, filter options and the AppUser token endpoints need a login JWT (an agent token gets 401 there). The AppUser token endpoints are Admin-only (whole AppUser controller); the report and filter options are Admin-only (403 for other signed-in users).
- Deferred: no price CRUD screen; OpenTelemetry (`claude_code.token.usage` / `cost.usage`) as a replacement for transcript parsing would only swap `lib/parse.js`.

## RowAudit history — 異動紀錄 badge on detail/edit pages (`database/rowaudit.sql`)
- `GET /api/rowaudit?tableName=Course&pkid=123` → `[{ dateTime, userName, actionType, actionDesc }]` for `TableName` + `PrimaryKeyValues` (= the record's pkid, also for AppRole/AppUser), `ORDER BY [DateTime] DESC, pkid DESC`. Missing/blank param → 400 `{ message }`; values longer than the columns → `[]`. Any signed-in user may read a table's history, except `AppUser`/`AppRole` (`RowAuditController.AdminOnlyTables`), which need Admin (403 `{ message }`). `tableName` must be one of the audited tables (`RowAuditController.AuditedTables`, case-insensitive) and only its canonical name reaches SQL: the column collation is width-insensitive, so a raw full-width `ＡｐｐＲｏｌｅ` would otherwise match AppRole rows. An unknown name returns `[]`. `dateTime` is Taipei time without an offset, shown as returned.
- Index `IX_RowAudit_TableName_PrimaryKeyValues` (TableName, PrimaryKeyValues, DateTime DESC) INCLUDE the other columns; plain, not filtered (QUOTED_IDENTIFIER OFF writers).
- UI `RowAuditBadge` (frontend.md › Custom pages): inline latest `{actionType} by {userName} · yyyy-MM-dd HH:mm`, else 尚無紀錄 No history; click → dialog with the full trail (reloaded on open). On the 6 detail pages and 6 edit forms (AppRole, AppUser, PublishStatus, Partner, CourseGroup, Course); hidden on new forms. Not on FeaturedPromoItem (inline editor) or My Profile.
