# Design: Course brochure PDF (課程簡介 PDF)

## Problem Statement
Sales reps send course information to customers as a document. Today they build it by hand: they copy course fields (課程名稱, 時數, 定價, 課程大綱 and other long texts) into a Word template and export or print it. The CMS already holds every one of these fields. The feature adds a 列印PDF action to the Course detail page that produces a customer-ready brochure from live data, so reps stop copy-pasting.

## Demand Evidence
- Reader is a customer or prospect. The request comes from the sales/customer-handout workflow, not from internal archiving.
- A specific rep who builds these docs is known, and their Word sample can be obtained.
- Also listed as an unbuilt item in `spec/sample1.spec.md:405` (列印PDF via `window.print()`) and `docs/claude/features.md:61`.
- Not yet measured: docs per week and minutes per doc. Capture both when collecting the sample (see Assignment).

## Status Quo
Reps copy fields from the old system/website into a Word template by hand, then export a PDF or print. Costs: time per doc (8 long-text fields, 課程大綱 is nvarchar(max)), and stale copies (a reused doc can carry an old 定價 or outline).

## Target User & Narrowest Wedge
- User: the sales rep who owns the Word template. Reader: their customer.
- Wedge: one button on one course, producing one brochure that matches the rep's sample. No batch export, no email, no per-customer editing.

## Constraints
- CMS is not live yet; this ships with the rest of the app. There is no frontend login, guard or token interceptor yet, and no `[Authorize]` on the API (only `POST api/auth/login` exists). The brochure route is exactly as open as every other route today; when auth lands, it must cover this new-tab route too.
- UI and content are Traditional Chinese; CJK text must render with no boxes and stay selectable.
- Repo conventions: Angular 20 standalone, signals, `inject()`, Jasmine spec next to each file, no new dependency without cause.
- Only the API on :5000 and `npm start` on :4200 run today; no server-side rendering infra exists.

## Premises (all agreed)
1. The PDF is a customer brochure modeled on the rep's Word sample, not a print of the admin screen. No 主代碼 / 簡介代碼 / 顯示順序 / 使用情形, and no buttons or links.
2. Content is loaded live from the DB each time and shows a generated date, plus a QR code to the public course page. (v1: data is as of when the detail page was loaded; reload before printing. Per-print re-fetch is deferred, X5 in TODOS.md.)
3. Reps send the PDF as-is; they do not hand-edit it per customer.
4. Traditional Chinese renders correctly and long fields break cleanly across A4 pages.
5. The action lives on the CMS Course detail page (staff-only once auth exists). There is no public PDF endpoint.

## Approaches Considered
- **A: Print-styled brochure page (chosen).** See below.
- **B: Server-side QuestPDF endpoint.** Not chosen for now: the Community License v3.0 (effective 2026-07-06) is free only under USD 1M consolidated revenue and excludes public companies, so a paid license is likely (https://questpdf.com/license/community.html, https://www.questpdf.com/license/guide.html). It also needs a bundled CJK font, and the layout lives in C# code that is slow to tune against a Word sample.
- **C: Headless Chromium (Playwright) on the server.** Not chosen: puts Chromium and its fonts on the server and adds the heaviest ops cost for a one-button feature.

- **QR print size (F1).** For `variant="print"`, after `renderer.render` resolves, QrCode sets `canvas.style.width` and `canvas.style.height` to `size + 'px'`. node-qrcode writes the inline style from `width` (canvas.js:9-10), so this reset is required. qr-code.spec asserts that the print variant has `canvas.width === 3 * size` and `canvas.style.width === size + 'px'`.
- **Toast/confirm in print (F2).** The app.scss `@media print` block adds `:host > :not(.layout) { display: none }`, so `<p-toast>` and `<p-confirmDialog>` (app.html:53-54) never print. The V2 styles.scss rule still covers body-appended overlays such as pTooltip. The manual checklist adds "print while a toast is visible".
- **D20 check scope and fallback (F3).**
  - The first print-preview check verifies, with Chrome defaults:
    - (a) no URL, date or title header with the top margin boxes left empty
    - (b) the footer text from `var(--brochure-footer, "")` renders
    - (c) page x / y renders
  - If (a) fails, it retries with the top boxes given `content: ""` placeholders.
  - If (b) fails, the footer moves to a `<style id="brochure-page">` injected on `beforeprint` with a literal `@page { @bottom-left { content: "…" } }` and removed on `afterprint`.
  - Only if (a) still fails is D20 reopened toward D8 + D18.
- **Built CSS check (F4).** RT2's Verify adds: after `npx ng build`, the emitted CSS contains `@bottom-right` and `counter(pages)`. If it doesn't, the `@page` block moves to styles.scss.
- **Listener lifecycle (F6).** The `beforeprint`/`afterprint` handlers are bound with `@HostListener('window:beforeprint')`/`('window:afterprint')` (or registered with `DestroyRef` cleanup), so they stop when the detail page is destroyed. Spec: destroy, dispatch `beforeprint`, assert `document.title` is unchanged.
- **Single today (F7).** course-detail computes `today = toIsoDate(new Date())` once per course load and passes it to `CourseBrochure` as `today = input.required<string>()`. Both banner and brochure call `qrOmitReason(course, today)` with that value. Spec: the same `today` gives the same reason in both.
- **Factory wiring (F5).** `CmsApiFactory` creates `Courses` in its constructor from `PublishStatuses`. FakeCourseRepository.cs:67 (description) and :143 (FK validation) read the injected `FakePublishStatusRepository`, and the static map is removed. The flip-flag test mutates the factory's status row before GET.
- **Footer string (F8).** A pure `toCssString(text)` builds the `--brochure-footer` value and replaces `JSON.stringify`:
  - truncate the title with `Array.from(title).slice(0, 30)` plus "…"
  - remove control characters
  - escape `\` and `"`
  - wrap the result in double quotes
  - Spec cases: a quote, a backslash, and a 60-character title containing an emoji.
- **No innerHTML (F9).** DT1 renders long texts with interpolation and `white-space: pre-wrap` only, never `[innerHTML]`.
- **Precedence spec (F11).** `qrOmitReason` table spec adds a row where a course is both unpublished and expired → `'unpublished'` (D9 order). Every spec touching dates uses `jasmine.clock().mockDate` or an explicit `today`.
